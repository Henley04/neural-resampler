neural-resampler ドキュメント

はじめに

neural-resampler は、HiFiSampler を純 Rust + ONNX で書き直した汎用の ニューラルリサンプラーエンジンです。

従来の UTAU 音源（ボイスバンク）は、録音サンプル（WAV）と各サンプルの切り出し パラメータ（oto.ini）の 2 つで構成されます。ピッチを変え、長さを変え、断片を つなぎ合わせて歌声にする役割を担うのがリサンプラーエンジンです。本プロジェクトの 目標はただ 1 つ：このエンジンだけを置き換え、そのほかは一切変更しないことです。

設計上のトレードオフ

項目説明
音源の互換性WAV と oto.ini は一切変更せず、そのまま流用
ボコーダPC-NSF-HiFiGAN（NSF アーキテクチャ、F0 条件付け）
F0 抽出FCPE（ONNX、16kHz）、内蔵 DSP へのフォールバック可
依存関係Python ランタイム不要、シングルバイナリで配布
ホスト互換OpenUtau / ネイティブ UTAU、プロトコル層は拡張可能

ピッチ変更と長さ変更の仕組み

ニューラル方式の巧みな点は、2 つの処理を分離したことです：

  • ピッチ変更 —— F0 曲線を直接変更します。ボコーダは F0 を条件とするため、 F0 を変えれば異なるピッチが得られ、波形のリサンプリングは不要です。そのため 従来のリサンプリング特有の金属音が発生しません。
  • 長さ変更 —— メルスペクトログラムを時間軸方向に伸縮／ループ結合します。 変わるのはフレーム数だけで、ピッチとは無関係です。

つまり 1 つのサンプルを任意の長さに引き伸ばし、任意のピッチで歌わせることが でき、両者は互いに干渉しません。

処理フロー

输入 WAV
   │
   ├─ Mel 分析（44.1kHz / 2048 FFT / 帧移 128）
   │
   ├─ F0 提取（FCPE，16kHz）  ──┐
   │                             ├─→ 按乐谱调整 F0
   ├─ 乐谱：音名 + pitchBend ────┘
   │
   ├─ Mel 时序拉伸到目标帧数
   │
   ├─ PC-NSF-HiFiGAN 声码器（Mel + F0 → 波形）
   │
   └─ 后处理（响度归一化、限幅、淡入淡出）→ 输出 WAV

どんなときに向いているか

向いているケース：従来の音源に、より自然な音質を持たせたい場合。Python 環境の ないマシンにデプロイしたい場合。読めて、改変でき、ほかのツールに組み込める Rust 実装が欲しい場合。

向いていないケース：存在しない音素を無から生成することを期待する場合 （あくまで結合合成であり、つなぎ方がより自然になるだけです）。GPU 加速が必要なのに CUDA/DirectML をインストールしたくない場合（デフォルトは CPU 動作で、使えますが 遅いです）。

ライセンス

MIT。使用するモデルはそれぞれの配布元のライセンスに従います。配布の前に ご自身でご確認ください。

インストール

方法 1：ビルド済みバイナリのダウンロード（推奨）

Releases ページ から、 お使いのプラットフォーム向けのアーカイブをダウンロードしてください。

プラットフォームファイル
Linux x86_64neural-resampler-<ver>-linux-x86_64.tar.gz
macOS Apple Siliconneural-resampler-<ver>-macos-aarch64.tar.gz
Windows x86_64neural-resampler-<ver>-windows-x86_64.zip

ビルド済みバイナリがまだ提供されていないプラットフォーム（macOS Intel、 Linux ARM64 など）では、ご自身で cargo build --release を実行してください。 成果物は target/release/resampler に生成されます。

各アーカイブには同名の .sha256 チェックサムファイルが付属しており、 ダウンロード後に確認できます：

shasum -a 256 -c neural-resampler-0.1.0-linux-x86_64.tar.gz.sha256
# Windows (PowerShell):
# (Get-FileHash -Algorithm SHA256 .\xxx.zip).Hash

展開後のディレクトリ構成：

neural-resampler-0.1.0-linux-x86_64/
├── resampler              # 主程序（Windows 为 resampler.exe）
├── config.resampler.yaml  # 默认配置，可直接改后用 --config 指定
├── download_models.sh     # 模型下载脚本（Linux/macOS）
├── download_models.ps1    # 模型下载脚本（Windows PowerShell）
├── models/                # 模型放置目录（初始为空）
├── docs/                  # 架构与模型说明
└── README.md LICENSE

アーカイブに ONNX モデルは含まれません。 モデルは約 100 MB あり、それぞれの 配布元ライセンスの制約を受けるため、リポジトリには同梱されていません。展開後に ./download_models.sh（Windows は .\download_models.ps1）を実行して取得して ください。詳細はモデルの取得を参照してください。

方法 2：ソースからビルド

Rust の安定版ツールチェーン（1.70+）が必要です。初回ビルド時に ONNX Runtime の ビルド済みライブラリが自動でダウンロードされます。

git clone https://github.com/Henley04/neural-resampler.git
cd neural-resampler
cargo build --release
# 产物：target/release/resampler

オプションの feature（GPU 加速）：

cargo build --release --features cuda      # NVIDIA CUDA
cargo build --release --features directml  # Windows DirectML
cargo build --release --features coreml    # macOS CoreML

⚠️ GPU 用 feature は相互排他です。複数を同時に有効化しないでください。また --all-features も使用しないでください。組み合わせた feature セットに一致する ビルド済みライブラリを ort が見つけられず、リンクに失敗します。

方法 3：独自の配布物をパッケージする

bash scripts/build_release.sh                 # 输出到 dist/
bash scripts/build_release.sh --features cuda

スクリプトはバイナリ・デフォルト設定・ドキュメントをパッケージ化し、ローカルに モデルが存在する場合はそれも同梱します。

インストールの確認

./resampler info        # 查看构建信息、配置指纹与模型状态
./resampler selftest    # 生成测试音并端到端跑一遍

info の出力で、ボコーダと FCPE の両方に [已就绪]（準備完了）と表示されて 初めて実際に使用可能です。[缺失]（欠落）と表示されている場合はエンジンが フォールバックします。詳細はトラブルシューティングを 参照してください。

モデルの入手

エンジンが実用レベルの音質を出すには ONNX モデルが必要です。モデルはリポジトリやリリース成果物には同梱されていません——合計で約 100 MB になり、 それぞれの出所のライセンスが再配布を許可しているとは限らないため、各自で入手してください。

配置場所

モデルは実行ファイルと同じ階層または指定した models/ ディレクトリに置きます：

ファイル役割必須
pc_nsf_hifigan.onnxボコーダ：Mel + F0 → 波形はい
fcpe.onnxF0 抽出（16kHz）いいえ、欠落時は内蔵 DSP にフォールバック
hnsep.onnxHN-SEP の調波/非調波分離いいえ

--models <DIR> で一時的に別のディレクトリを指定できます：

./resampler --models /path/to/models info

ワンコマンドでのダウンロード

リリース成果物にはダウンロードスクリプトが同梱されています（bash と PowerShell の 2 種類、処理内容は同じ）：

./download_models.sh      # Linux / macOS / Git Bash

powershell -ExecutionPolicy Bypass -File .\download_models.ps1    # Windows PowerShell

リポジトリ内にもあります（scripts/download_models.sh と scripts/download_models.ps1）。 スクリプトは自動リトライに対応し、ダウンロード後に SHA-256 検証を行います （基準は v0.1.0 とともに検証済みのバージョン）。ファイルが破損している、または上流で差し替えられていた場合はインストールを拒否して通知します。

ダウンロード元とミラー高速化

スクリプトはデフォルトで GitHub に直接接続し（raw.githubusercontent.com）、gh-proxy ミラーによる高速化を内蔵しています：

  1. 自動検出：GitHub への直接接続が不通な場合、自動的にミラーへ切り替えて通知します

  2. 低速時の切り替え：平均ダウンロード速度が 10 秒間 100KB/s 未満で、現在 direct 接続のときは ミラーへ切り替えるか尋ねます（NR_MODEL_AUTO_SWITCH=1 なら尋ねずに自動切り替えします）； direct 接続のリトライを使い切った後も、最後の 1 回は自動的にミラーを使います

  3. ミラーの強制：NR_MODEL_MIRROR を設定すると、指定したミラープレフィックスを直接使います （gh-proxy 形式：プレフィックス + 完全な元 URL）：

    NR_MODEL_MIRROR=https://gh-proxy.com/ ./download_models.sh

    自前デプロイや他の gh-proxy インスタンスに差し替えることもできます。

上流のモデル更新で検証が通らなくなった場合は、新しいバージョンが使えることを確認したうえで NR_MODEL_SKIP_CHECKSUM=1 を設定して一時的に検証をスキップできます——出所が信頼できることを確認してから行ってください （ミラーの内容が改ざんされていても検証で捕捉されます）。

手動での入手

スクリプトが使えない場合は手動でダウンロードし、上の表のファイル名にリネームして models/ に置きます：

  1. FCPE —— CNChTu/FCPE のリリースページから fcpe.onnx を取得
  2. PC-NSF-HiFiGAN —— ONNX 形式が必要です。手元に .ckpt 重みしかない場合は、 リポジトリ内の変換スクリプトを使えます： 
    python scripts/convert_vocoder_to_onnx.py --ckpt model.ckpt --out models/pc_nsf_hifigan.onnx

モデルの動作確認

./resampler info

次の 3 行に注目してください：

声码器  : "models/pc_nsf_hifigan.onnx"  [已就绪]
FCPE    : "models/fcpe.onnx"  [已就绪]
HN-SEP  : "models/hnsep.onnx"  [缺失]
  • ボコーダ [缺失] → Stub バックエンドにフォールバックし、音は出ますが音質は実用になりません
  • FCPE [缺失] → 内蔵 DSP による F0 抽出にフォールバックします。通常どおり動作しますが、歌声用途ではやや不安定になります
  • HN-SEP [缺失] → 正常です。オプションの拡張機能です

ライセンス

各モデルの出所であるリポジトリ/リリースページのライセンス条件に従ってください。モデルを独自の配布物に同梱する前に、 必ずライセンスで許可されているか確認してください。

クイックスタート

インストールとモデルの取得が済んでいるものとします。

ステップ 1：セルフテスト

./resampler selftest

このコマンドは 440Hz のテスト音を生成し、パイプライン全体をエンドツーエンドで 実行して、最後に次の内容を表示します：

已生成测试输入: "target/selftest/selftest_input.wav"
输出: "target/selftest/selftest_output.wav"（24696 样本 / 560.0ms / 峰值 0.254）
自检通过

自检通过（セルフテスト合格）と表示されればインストールは完了です。デフォルトの 出力先は target/selftest/ で、--out-dir で変更できます：

./resampler selftest --out-dir /tmp/nr-test

ステップ 2：バックエンドの状態を確認

./resampler info

最後の 2 行に注目してください：

声码器后端: onnxruntime
F0 后端    : fcpe-onnx

stub / world-dio と表示されている場合はモデルが見つかっていないので、 モデルの取得に戻ってください。

ステップ 3：1 音レンダリングする

./resampler render voice/_a.wav out.wav A4

パスを 2 つ渡すだけでも実行でき、ほかの引数にはすべてデフォルト値 （A4、ベロシティ 100、長さ 1000ms）が入ります。全引数を指定すると：

./resampler render voice/_a.wav out.wav A4 100 "g-3" 30 500 60 -50 100 0 '!120' AA

出力は次のようになります：

已写出 "out.wav"：87 帧 / 500.0ms / 后端 onnxruntime / F0 fcpe-onnx / 耗时 812.3ms

ステップ 4：エディタで使う

バイナリ自体がリサンプラーなので、UTAU プロトコルに従って直接呼び出せます：

resampler in.wav out.wav C4 100 "" 0 500 60 -50 100 0 !120 AA

エディタへの組み込み手順はUTAU で使うまたは OpenUtau で使うを参照してください。

一括レンダリング

複数組の UTAU パラメータを 1 つのファイルに 1 行ずつ書き込みます：

# list.txt
voice/_a.wav out/a.wav C4 100 "" 0 500 60 -50 100 0 !120 AA
voice/_i.wav out/i.wav D4 100 "" 0 500 60 -50 100 0 !120 AA

./resampler batch list.txt --jobs 4

# で始まる行は無視されます。--jobs 0 で並列度を自動決定します。

設定を変更する

デフォルト設定を書き出し、必要に応じて編集してから --config で指定します：

./resampler config my.yaml
# 编辑 my.yaml
./resampler --config my.yaml render voice/_a.wav out.wav A4

詳細な設定項目は設定ファイルを参照してください。

UTAU で使う

バイナリ自体がリサンプラーであり、追加のラッパースクリプトは不要です。UTAU は 決められた順序で引数を渡すので、そのまま直接呼び出せます：

resampler in.wav out.wav C4 100 "" 0 500 60 -50 100 0 !120 AA

引数の意味

#引数意味単位 / デフォルト
1in.wav入力サンプルのパス—
2out.wav出力パス—
3pitch音名C4
4velocityベロシティデフォルト 100
5flagsレンダリング フラグデフォルトは空
6offset左ブランクミリ秒、デフォルト 0
7length要求する長さミリ秒、デフォルト 1000
8consonant子音部ミリ秒、デフォルト 0
9cutoff右側ブランクミリ秒、多くの場合負、デフォルト 0
10volume音量パーセント、デフォルト 100
11modulationモジュレーションパーセント、デフォルト 0
12tempoテンポ!120 または 120
13pitchBendピッチ曲線Base64+RLE エンコード、デフォルト AA

⚠️ 第 7 引数 length の単位はミリ秒であってサンプル数ではありません。 44100 を渡すと 1 秒ではなく 44.1 秒の出力になります。最も引っかかりやすい 落とし穴です。

cutoff が負になるのは正常です（右側の重なり領域を表します）。プログラムは負の 引数を受け付けます。

対応しているフラグ

フラグは g-3P60HG20 のような形式で、長いフラグを優先して解釈されます （/ 区切り文字は無視されます）。現在のバージョンで実際に効果があるのは 以下のみで、それ以外のフラグは解釈されますが出力には影響しません：

フラグ意味値
gジェンダー/音色シフトg-3 は −3 を意味し、単位は約 1/100 半音。省略時は設定の processing.gender を使用
tピッチの微調整整数、デフォルト 0
Aピッチ変化に応じた振幅変調整数、デフォルト 0（オフ）
Pラウドネス正規化の強さP60 = 60%、デフォルト 100
Heループ結合の強制有効化スイッチ型。記述すれば有効
HGgrowl（唸り）HG20 = 20% の強さ

UTAU での設定

  1. resampler.exe を固定のディレクトリに置きます（パスに空白や日本語文字を 含めないでください。UTAU の互換性はあまり高くありません）
  2. UTAU を開く →「ツール」→「オプション」→「音源プラグイン / Resampler」
  3. 「カスタム」を選択するか、設定画面にリサンプラーのフルパスを直接入力します
  4. 確定して 1 音レンダリングし、試聴します

UTAU が「resampler が応答しません」と表示したり出力が空になったりする場合は、 まず同じ引数をコマンドラインから手動で 1 回実行し、プログラム自身のエラーを確認 してください。ほとんどの問題はコマンドラインで一目でわかります。

ログとデバッグ

UTAU から呼び出した場合はターミナル出力が見えないため、ログレベルを上げて ファイルにリダイレクトできます：

resampler --log-level debug in.wav out.wav C4 100 "" 0 500 60 -50 100 0 !120 AA 2> debug.log

--log-format json を指定すると構造化ログが出力され、スクリプトでの分析に 便利です。

パフォーマンスのヒント

サンプルの初回レンダリング時にはメルスペクトログラム解析と F0 抽出が行われ、 その結果は同じディレクトリの .nrc ファイル（zstd 圧縮）としてキャッシュされ ます。同じ入力の 2 回目のレンダリングは明らかに速くなります。キャッシュキーには 元ファイルのサイズ・更新時刻・設定のフィンガープリントが含まれるため、設定を 変更すると自動的に無効化されて再構築されます。キャッシュを手動で削除する 必要はありません。

OpenUtau で使う

OpenUtau は Resamplers ディレクトリでサードパーティのリサンプラーを管理します。 標準のリサンプラープロトコルに従って 13 個の引数が渡され、ネイティブ UTAU と まったく同じなので、追加のパラメータテンプレートの設定は不要です。

設定手順

OpenUtau 公式 wiki に従います：

  1. resampler（Windows は resampler.exe）を OpenUtau の Resamplers フォルダに入れます：
    • Windows：OpenUtau のプログラムディレクトリ下の Resamplers
    • Linux：~/.local/share/OpenUtau/Resamplers
    • 実行ファイルを OpenUtau のメインウィンドウにドラッグし、「Install as resampler」 を選ぶ方法もあります（0.1.119+）
  2. レンダラーを CLASSIC に切り替えます
  3. レンダラーの横の ⚙ 歯車アイコン をクリックし、Resampler ドロップダウンで本リサンプラーを選択します
  4. プロジェクトを再レンダリングします

任意：Resamplers ディレクトリに実行ファイルと同名の .yaml（例：resampler.yaml）を Resampler Manifest として置くと、本エンジンが対応するフラグ（expression）を OpenUtau に 宣言でき、expression パネルに推奨値と範囲が表示されます。

モデルの配置（重要）

リサンプラーをインストールすると、OpenUtau は実行ファイルを自身の Resamplers/ ディレクトリへコピーします。レンダリング時の作業ディレクトリは OpenUtau のインストールルートであり、そこに models/ は存在しません。モデルが 欠落している場合、エンジンはもう静かに劣化しません：レンダリングは拒否され、 OpenUtau に三言語のエラーダイアログ（対処法つき）が表示され、リサンプラー実行 ファイルの隣に MODEL-MISSING-READ-ME.txt 警告ファイルが作成されます。

モデルディレクトリは以下の順で解決されます：

  1. コマンドラインの --models（OpenUtau は渡さない。CLI 手動実行専用）
  2. 環境変数 NR_MODELS_DIR（推奨：ダウンロードスクリプトが自動設定、下記参照）
  3. 実行ファイルと同じ階層の models/（つまり Resamplers/models/）
  4. 作業ディレクトリの models/（リリースパッケージ配置）

OpenUtau では 2 か 3 を推奨します：

  • 推奨：リリースパッケージのディレクトリで download_models.sh / download_models.ps1 を一度実行してください。モデルのダウンロードと検証の後、 スクリプトが自動的に NR_MODELS_DIR をユーザー環境変数に書き込みます （NR_SKIP_ENV=1 でスキップ）。以降、リサンプラーがどこにコピーされても モデルを見つけられるため、exe を OpenUtau にドラッグするだけで他の設定は不要です。 ⚠ この方法を使っている間、その models/ ディレクトリを移動・リネームしないで ください。移動する場合はスクリプトを再実行するか NR_MODELS_DIR を手動更新。
  • または models/ を Resamplers/models/（実行ファイルと同じ階層）に置きます。

設定後、resampler info を実行し、ボコーダのバックエンドが onnxruntime と 表示される（stub でない）ことを確認してください。

オフライン検証のために意図的に劣化バックエンドを使いたい場合：--allow-stub を付けるか NR_ALLOW_STUB=1 を設定してください。selftest と info サブコマンドは影響を受けません。

パスに関する注意

  • Resamplers ディレクトリに置く（またはドラッグ＆ドロップでインストールする）と、パスは OpenUtau が管理するため手動指定は不要です
  • macOS / Linux ではバイナリに実行権限を付与してください：chmod +x resampler
  • macOS で初回実行時に Gatekeeper にブロックされた場合（バイナリは未署名です）、「システム設定 → プライバシーとセキュリティ」で許可するか、次を実行します：xattr -d com.apple.quarantine ./resampler
  • macOS / Linux で Windows 版リサンプラーを実行するには Wine の設定が必要です（Tools > Preferences > Advanced > Wine Path）。本リポジトリはネイティブの macOS/Linux 版を提供しているため、Wine は不要です

設定が反映されたかの確認

OpenUtau で 1 音レンダリングし、出力された WAV を確認します。同じ引数を コマンドラインから単独で検証することもできます：

./resampler render <样本路径> /tmp/check.wav C4 100 "" 0 500 60 -50 100 0 '!120' AA

コマンドラインでは鳴るのに OpenUtau では鳴らない場合、問題のほとんどはパスか 権限にあり、エンジン自体ではありません。

クラシック系リサンプラーとの違い

OpenUtau がデフォルトで同梱する world 系リサンプラー（worldline など）は、接合部で 位相合わせを行います。本エンジンはニューラルボコーダの方式で、モデルが合成した波形を 出力します。そのため：

  • 音質は自然な発声に近づきますが、毎回のレンダリング結果は完全に同一です（ランダム性はありません）
  • 長い音符はループ結合に依存します。He フラグで強制的に有効化できます
  • CPU 推論のため 1 回のレンダリングにはクラシック系リサンプラーより時間がかかり、キャッシュの併用を推奨します

パフォーマンス

初回レンダリングにはモデル読み込みのオーバーヘッド（数十ミリ秒程度）があります。以降は 1 音あたりの所要時間が主にメルスペクトログラム解析とボコーダの推論で決まります。キャッシュを 有効にすると、同じ入力の再レンダリングが大幅に速くなります。

GPU 加速が必要な場合は、--features cuda（NVIDIA）または --features directml（Windows）を 付けてご自身でビルドしてください。詳細はインストールを参照してください。

コマンドラインリファレンス

2 つの呼び出し形式

1）UTAU プロトコル（サブコマンドなし） —— ホストエディタから使用します。引数の順序は固定：

resampler in.wav out.wav C4 100 "" 0 500 60 -50 100 0 !120 AA

2）明示的サブコマンド —— 手動で使用する場合：

resampler render  in.wav out.wav A4
resampler batch   list.txt --jobs 4
resampler info
resampler selftest
resampler config  my.yaml

プログラムはまず、引数が UTAU 呼び出しらしく見えるか（位置引数が 4 つ以上で、第 1 引数がサブコマンド名でない）を判定します。 そうであればプロトコルパスを通し、そうでなければサブコマンドとして解析します。

サブコマンドの前に置けます（後ろに置いても可。いずれも global です）：

render

UTAU プロトコルに従って 1 音をレンダリングします。

resampler render <IN> <OUT> [pitch] [velocity] [flags] [offset] [length]
                 [consonant] [cutoff] [volume] [modulation] [tempo] [pitchBend]

必須は最初の 2 引数のみで、残りの既定値は C4 100 "" 0 1000 0 0 100 0 !120 AA です。 引数の意味は UTAU パラメータ表 を参照してください。

./resampler render voice/_a.wav out.wav A4 100 "g-3" 30 500 60 -50 100 0 '!120' AA

出力例：

已写出 "out.wav"：87 帧 / 500.0ms / 后端 onnxruntime / F0 fcpe-onnx / 耗时 812.3ms

batch

一括レンダリング。リストファイルの各行が 1 組の UTAU パラメータで、空行と # で始まる行はスキップされます。

# list.txt
voice/_a.wav out/a.wav C4 100 "" 0 500 60 -50 100 0 !120 AA
voice/_i.wav out/i.wav D4 100 "" 0 500 60 -50 100 0 !120 AA

./resampler batch list.txt --jobs 4

--jobs 0 は直列を意味し、デフォルトは 0 です。並列時の出力順序は保証されません。

バッチ全体で 1 つのエンジンインスタンスを共有します：ONNX モデルの読み込みは 1 回だけで、行ごとに 97MB のモデルを 再読み込みすることはありません。推論セッションは内部のミューテックスで保護されているため、--jobs による高速化の多くは 前処理の並列化と再読み込みの省略から得られるもので、推論部分は直列のままです——自動バッチ処理のような場面では --jobs を物理コア数の半分程度にしておけばよく、無闇に増やしても追加の効果はありません。

440Hz のテスト音を生成し、パイプラインをエンドツーエンドで実行して出力が空でないことを検証します。インストールが正常かの確認に使います。

現在有効な設定を YAML としてエクスポートします。それをベースに編集するのに便利です。

終了コード

0 は成功、0 以外は失敗です。失敗メッセージは stderr に出力されます。--log-level debug を上げると、 モデル読み込みやバックエンド選択などの詳細が見られます。

F0 生成モード

F0（基本周波数）カーブは、出力がどの高さで歌うか、どのように滑るかを決めます。設定 f0.mode で F0 をどこから取得するかを決めます。

モード動作適した場面
scoreF0 が完全にスコア（音名 + pitchBend）から決まり、元の HiFiSampler と同じスコアに正確に合わせたい
sourceサンプル自身の F0 カーブをまとめて目標ピッチへ移調する元サンプルのビブラート/滑音を残したい
hybridスコアが絶対ピッチを与え、サンプルの F0 が自然なずれと有声音判定を担うデフォルト。正確さと自然さの両立

score

サンプル自身のピッチを完全に無視し、スコアに従って F0 を生成します。結果は最も制御しやすく MIDI に忠実ですが、 サンプルに本来含まれるビブラートや音色の揺らぎが失われ、「電子的」に聞こえることがあります。

向いているケース：ピッチを厳密に合わせたいプロジェクト、ハーモニーの積み重ね。

source

サンプル自身の F0 カーブを丸ごと目標ピッチへ平行移動します。サンプルのビブラート、滑音、息のニュアンスがすべて保たれ、 最も「元の音源らしい」響きになりますが、絶対ピッチはスコアと合いません（サンプル自体が高めに歌っていれば、そのぶん高めのままです）。

向いているケース：自然さを重視する場合、スコア自体がサンプルから採譜したものである場合。

hybrid（デフォルト）

スコアを絶対的な基準にし、そこへサンプル F0 の相対的なずれを重ね合わせます。さらにサンプルの有声音判定で 有声/無声フレームを区別します。これによりピッチを合わせながら、自然な揺らぎを保てます。

ずれの量は f0.max_deviation_cents で制限されます（デフォルト 100 cent、半音 1 つぶん）。 サンプルが極端にずれてピッチを狂わせるのを防ぎます。基準カーブの平滑化ウィンドウは f0.smoothing_ms で制御します（デフォルト 40ms）。

向いているケース：ほぼすべての場面。スコアにもっと合わせたいなら max_deviation_cents を小さく、 もっと自然にしたいなら大きくします（または source を使います）。

選び方

まずデフォルトの hybrid を使ってください。ピッチの正確さが足りないと感じたら score の方へ、 硬すぎると感じたら source の方へ。3 者の違いは 1 音では分かりにくくても、 旋律としてつなげば聞き分けられます。

F0 バックエンドについて

f0.backend: auto の場合の優先順位：

  1. FCPE（ONNX） —— 歌声の場面で最も安定。fcpe.onnx が必要
  2. 内蔵 DSP —— DIO/Harvest 方式。モデル不要
  3. スコアのみ —— 最後のフォールバック

resampler info の F0 后端 の行に、現在実際に使われているバックエンドが表示されます。

FCPE の出力は 360 クラスの cent 分類 latent であり、直接の F0 値ではありません。 プログラムは公式の手順に沿ってデコードします：局所 argmax（±4 クラス）の加重平均 → f0 = 10 · 2^(cent/1200)、 信頼度が f0.uv_threshold（デフォルト 0.006）以下のフレームは無声と判定されます。

どの層の問題かを見分ける

この順序で調べると、すばやく絞り込めます：

1. モデルはあるか？

./resampler info

2 つとも [已就绪] なら揃っています。

2. エンジンは音を出せるか？

./resampler selftest

内蔵生成の 440Hz テスト音で一通り実行します。ここで失敗するなら問題はエンジン/モデル側にあり、 あなたの音源とは無関係です。

3. あなたのサンプルは音を出せるか？

./resampler render <你的样本> /tmp/t.wav C4

selftest が通ってここで失敗するなら、問題はサンプル自体（形式、サンプルレート、長さ）にあります。

4. エディタのパラメータは正しいか？

コマンドラインで鳴るのにエディタで鳴らないなら、問題はエディタ側の呼び出し引数かパス設定にあります。

ログ

ログレベルを上げると、モデル読み込み、バックエンド選択、Mel の形状、F0 の統計などの詳細が見られます：

./resampler --log-level debug --models ./models info

--log-format json は構造化ログを出力し、スクリプトでの処理に便利です：

./resampler --log-format json render a.wav b.wav C4 2>&1 | grep '"level":"error"'

load-dynamic のバージョン制約

デフォルトの配布成果物は ONNX Runtime をバイナリに静的リンクしているため、この問題は起きません。 しかし load-dynamic 方式で自分でビルドした場合（実行時に libonnxruntime.so / onnxruntime.dll を読み込む）には、分かりにくい落とし穴があります：

dylib のバージョンは、ort-sys がビルド時に期待するバージョンと正確に一致している必要があります（例：1.28.0）。 隣接するバージョン（例：1.19.2、1.22.0）では——レンダリングはまったく正常ですが、プロセスの終了時に SIGSEGV が発生します（exit 139）。クラッシュ地点は exit() → ld-linux 析构 → libonnxruntime で、 gdb のスタックトレースはライブラリのアンロード問題に見えますが、実際は ABI 非互換によるクリーンアップパスの範囲外アクセスです。

調べ方：

  • 読み込まれているライブラリのバージョンを確認：ldd resampler | grep onnxruntime のあと、その so のバージョンを調べる
  • ビルド設定に対応する正確なバージョンに替えるか、静的リンク（デフォルトの配布モード）へ切り替える
  • 終了コードをチェックする CI ホストでは、この問題は「レンダリングは成功したがタスクが失敗」として現れます

キャッシュ関連

キャッシュファイルは入力と同じディレクトリの .nrc（zstd 圧縮）です。キャッシュキー = ソースファイルのパス + サイズ + mtime + 設定フィンガープリント + サンプルレート なので：

  • 設定を変更 → 自動で無効化して再構築
  • ソースファイルを変更 → 自動で無効化して再構築
  • .nrc を手動で削除しても、次のレンダリングが 1 回遅くなるだけで、壊れません

キャッシュを無効化するには：cache.enabled: false。

それでも解決しないとき

以下の情報を添えて Issues で質問してください：

  • ./resampler info の完全な出力
  • 再現に使ったコマンドラインと引数
  • --log-level debug のログ
  • OS とプラットフォーム

よくある質問

音源（ボイスバンク）を変更する必要はありますか？

必要ありません。WAV と oto.ini はそのまま使えます。エディタのリサンプラー設定を本プログラムに向けるだけです。

リリースパッケージにモデルが入っていないのはなぜですか？

理由は 2 つあります。モデルの合計が約 100 MB になることと、ライセンスが再配布を許可していない場合があることです。 そのためモデルは利用者各自が入手します。リリースパッケージには download_models.sh （Windows は download_models.ps1）が同梱されています。

モデルがなくても動きますか？

用途によります。resampler selftest と resampler info は影響を受けず、 パイプラインの動作確認ができます。ただし render / batch / UTAU プロトコルの レンダリングは、モデルが欠落していると明示的なエラーで終了します（対処法つきの 三言語メッセージ）。実用にならない音声は出力されません。オフライン検証のために 意図的に劣化バックエンドを使いたい場合は、--allow-stub を付けるか NR_ALLOW_STUB=1 を設定してください。

OpenUtau でのレンダリングが「ボコーダーモデルが見つからない」エラーになる？

OpenUtau はリサンプラーをインストールするとき、実行ファイルを自身の Resamplers/ ディレクトリへコピーします——モデルは同行しません。v0.1.3 から、 この状況は静かな劣化ではなくなりました（以前は音が出るが音質が劣化し、エラーも 表示されませんでした）。現在はレンダリングが失敗して三言語のエラーダイアログが 表示され、リサンプラーの隣に MODEL-MISSING-READ-ME.txt が生成されます。 対処（どちらか）：

  1. 推奨：リリースパッケージのディレクトリで download_models.sh / download_models.ps1 を一度実行——スクリプトが自動的に NR_MODELS_DIR を ユーザー環境変数に書き込みます（以降 exe はどこに置いても構いません。ただし この方法使用中は models ディレクトリを移動しないでください）
  2. または models/ を Resamplers/models/（実行ファイルと同じ階層）にコピー

その後 resampler info を実行し、ボコーダのバックエンドが stub ではなく onnxruntime と表示されることを確認してください。

最初のレンダリングが遅いのはなぜですか？

初回は Mel 分析と F0 抽出を行い、さらに ONNX モデルを読み込む必要があるためです。同じ入力の 2 回目のレンダリングはキャッシュが効き、 大きく速くなります。旋律全体をレンダリングするとき、モデルの読み込みは 1 回だけです。

GPU はサポートされていますか？

サポートされていますが、対応する feature を付けて自分でビルドする必要があります：

cargo build --release --features cuda      # NVIDIA
cargo build --release --features directml  # Windows
cargo build --release --features coreml    # macOS

複数を同時に有効にしないでください。また --all-features も使わないでください——feature は相互排他で、リンクに失敗します。 デフォルトの成果物は CPU です。

出力の長さはどう制御しますか？

7 番目の引数 length で、単位はミリ秒です。1 秒の出力が欲しければ 1000 を渡します。 44100 を渡すと 44.1 秒になります。

UTAU と OpenUtau の両方に対応していますか？

対応しています。両者とも同じ 13 引数プロトコルを使うので、1 つのバイナリで足ります。 設定方法は UTAU と OpenUtau を参照してください。

すべてのフラグが効きますか？

いいえ。現在実際に効いているのは g、t、A、P、He、HG の 6 つだけで、 それ以外のフラグは解釈されますが、現時点では出力に影響しません。詳しくは UTAU パラメータ を参照してください。

出力は決定論的ですか？

はい。同じ入力 + 同じ引数 + 同じ設定なら、出力はサンプル単位で一致します。ランダム性はありません。

音がこもる/歪む場合は？

99% は Mel パラメータとモデル仕様の不一致です。デフォルトの mel.* 設定に戻し、 mel_scale: slaney、sample_rate: 44100、n_mels: 128 を確認してください。 デフォルト以外のモデルに差し替えた場合は、これらのパラメータを必ず同時に変更してください。

キャッシュファイルは削除できますか？

削除できます。削除しても次のレンダリングが少し遅くなるだけです。キャッシュキーにはソースファイルのサイズ、更新時刻、設定フィンガープリントが含まれるため、 通常は手動でのクリーンアップは不要です。

商用利用はできますか？

コードは MIT です。ただしモデルのライセンスはそれぞれの出所に従います。商用利用の前にご自身で確認してください。 これもモデルをリポジトリに同梱していない理由の 1 つです。
