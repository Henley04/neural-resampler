# はじめに

**neural-resampler** は、HiFiSampler を**純 Rust + ONNX** で書き直した汎用の
ニューラルリサンプラーエンジンです。

従来の UTAU 音源（ボイスバンク）は、録音サンプル（WAV）と各サンプルの切り出し
パラメータ（`oto.ini`）の 2 つで構成されます。ピッチを変え、長さを変え、断片を
つなぎ合わせて歌声にする役割を担うのがリサンプラーエンジンです。本プロジェクトの
目標はただ 1 つ：**このエンジンだけを置き換え、そのほかは一切変更しない**ことです。

## 設計上のトレードオフ

| 項目 | 説明 |
| --- | --- |
| 音源の互換性 | WAV と `oto.ini` は一切変更せず、そのまま流用 |
| ボコーダ | PC-NSF-HiFiGAN（NSF アーキテクチャ、F0 条件付け） |
| F0 抽出 | FCPE（ONNX、16kHz）、内蔵 DSP へのフォールバック可 |
| 依存関係 | Python ランタイム不要、シングルバイナリで配布 |
| ホスト互換 | OpenUtau / ネイティブ UTAU、プロトコル層は拡張可能 |

## ピッチ変更と長さ変更の仕組み

ニューラル方式の巧みな点は、2 つの処理を**分離**したことです：

* **ピッチ変更** —— F0 曲線を直接変更します。ボコーダは F0 を条件とするため、
  F0 を変えれば異なるピッチが得られ、波形のリサンプリングは不要です。そのため
  従来のリサンプリング特有の金属音が発生しません。
* **長さ変更** —— メルスペクトログラムを時間軸方向に伸縮／ループ結合します。
  変わるのはフレーム数だけで、ピッチとは無関係です。

つまり 1 つのサンプルを任意の長さに引き伸ばし、任意のピッチで歌わせることが
でき、両者は互いに干渉しません。

## 処理フロー

```
输入 WAV
   │
   ├─ Mel 分析（44.1kHz / 2048 FFT / 帧移 128）
   │
   ├─ F0 提取（FCPE，16kHz）  ──┐
   │                             ├─→ 按乐谱调整 F0
   ├─ 乐谱：音名 + pitchBend ────┘
   │
   ├─ Mel 时序拉伸到目标帧数
   │
   ├─ PC-NSF-HiFiGAN 声码器（Mel + F0 → 波形）
   │
   └─ 后处理（响度归一化、限幅、淡入淡出）→ 输出 WAV
```

## どんなときに向いているか

**向いているケース**：従来の音源に、より自然な音質を持たせたい場合。Python 環境の
ないマシンにデプロイしたい場合。読めて、改変でき、ほかのツールに組み込める Rust
実装が欲しい場合。

**向いていないケース**：存在しない音素を無から生成することを期待する場合
（あくまで結合合成であり、つなぎ方がより自然になるだけです）。GPU 加速が必要なのに
CUDA/DirectML をインストールしたくない場合（デフォルトは CPU 動作で、使えますが
遅いです）。
