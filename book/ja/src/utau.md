# UTAU で使う

バイナリ自体がリサンプラーであり、追加のラッパースクリプトは不要です。UTAU は
決められた順序で引数を渡すので、そのまま直接呼び出せます：

```bash
resampler in.wav out.wav C4 100 "" 0 500 60 -50 100 0 !120 AA
```

## 引数の意味

| # | 引数 | 意味 | 単位 / デフォルト |
| --- | --- | --- | --- |
| 1 | `in.wav` | 入力サンプルのパス | — |
| 2 | `out.wav` | 出力パス | — |
| 3 | `pitch` | 音名 | `C4` |
| 4 | `velocity` | ベロシティ | デフォルト `100` |
| 5 | `flags` | レンダリング フラグ | デフォルトは空 |
| 6 | `offset` | 左ブランク | **ミリ秒**、デフォルト `0` |
| 7 | `length` | 要求する長さ | **ミリ秒**、デフォルト `1000` |
| 8 | `consonant` | 子音部 | **ミリ秒**、デフォルト `0` |
| 9 | `cutoff` | 右側ブランク | **ミリ秒**、多くの場合負、デフォルト `0` |
| 10 | `volume` | 音量 | パーセント、デフォルト `100` |
| 11 | `modulation` | モジュレーション | パーセント、デフォルト `0` |
| 12 | `tempo` | テンポ | `!120` または `120` |
| 13 | `pitchBend` | ピッチ曲線 | Base64+RLE エンコード、デフォルト `AA` |

> ⚠️ **第 7 引数 `length` の単位はミリ秒であってサンプル数ではありません。**
> `44100` を渡すと 1 秒ではなく 44.1 秒の出力になります。最も引っかかりやすい
> 落とし穴です。

`cutoff` が負になるのは正常です（右側の重なり領域を表します）。プログラムは負の
引数を受け付けます。

## 対応しているフラグ

フラグは `g-3P60HG20` のような形式で、長いフラグを優先して解釈されます
（`/` 区切り文字は無視されます）。**現在のバージョンで実際に効果があるのは
以下のみ**で、それ以外のフラグは解釈されますが出力には影響しません：

| フラグ | 意味 | 値 |
| --- | --- | --- |
| `g` | ジェンダー/音色シフト | `g-3` は −3 を意味し、単位は約 1/100 半音。省略時は設定の `processing.gender` を使用 |
| `t` | ピッチの微調整 | 整数、デフォルト `0` |
| `A` | ピッチ変化に応じた振幅変調 | 整数、デフォルト `0`（オフ） |
| `P` | ラウドネス正規化の強さ | `P60` = 60%、デフォルト `100` |
| `He` | ループ結合の強制有効化 | スイッチ型。記述すれば有効 |
| `HG` | growl（唸り） | `HG20` = 20% の強さ |

## UTAU での設定

1. `resampler.exe` を固定のディレクトリに置きます（パスに**空白や日本語文字を
   含めない**でください。UTAU の互換性はあまり高くありません）
2. UTAU を開く →「ツール」→「オプション」→「音源プラグイン / Resampler」
3. 「カスタム」を選択するか、設定画面にリサンプラーのフルパスを直接入力します
4. 確定して 1 音レンダリングし、試聴します

UTAU が「resampler が応答しません」と表示したり出力が空になったりする場合は、
まず同じ引数をコマンドラインから手動で 1 回実行し、プログラム自身のエラーを確認
してください。ほとんどの問題はコマンドラインで一目でわかります。

## ログとデバッグ

UTAU から呼び出した場合はターミナル出力が見えないため、ログレベルを上げて
ファイルにリダイレクトできます：

```bash
resampler --log-level debug in.wav out.wav C4 100 "" 0 500 60 -50 100 0 !120 AA 2> debug.log
```

`--log-format json` を指定すると構造化ログが出力され、スクリプトでの分析に
便利です。

## パフォーマンスのヒント

サンプルの初回レンダリング時にはメルスペクトログラム解析と F0 抽出が行われ、
その結果は同じディレクトリの `.nrc` ファイル（zstd 圧縮）としてキャッシュされ
ます。同じ入力の 2 回目のレンダリングは明らかに速くなります。キャッシュキーには
元ファイルのサイズ・更新時刻・設定のフィンガープリントが含まれるため、設定を
変更すると自動的に無効化されて再構築されます。**キャッシュを手動で削除する
必要はありません**。
