# 在 UTAU 中使用

二进制本身即 resampler，不需要额外的包装脚本。UTAU 会按约定的顺序传入参数，
直接调用即可：

```bash
resampler in.wav out.wav C4 100 "" 0 500 60 -50 100 0 !120 AA
```

## 参数含义

| # | 参数 | 含义 | 单位 / 默认 |
| --- | --- | --- | --- |
| 1 | `in.wav` | 输入样本路径 | — |
| 2 | `out.wav` | 输出路径 | — |
| 3 | `pitch` | 音名 | `C4` |
| 4 | `velocity` | 力度 | 默认 `100` |
| 5 | `flags` | 渲染标记 | 默认空 |
| 6 | `offset` | 左空白 | **毫秒**，默认 `0` |
| 7 | `length` | 要求长度 | **毫秒**，默认 `1000` |
| 8 | `consonant` | 子音部 | **毫秒**，默认 `0` |
| 9 | `cutoff` | 右侧空白 | **毫秒**，常为负，默认 `0` |
| 10 | `volume` | 音量 | 百分比，默认 `100` |
| 11 | `modulation` | 调制 | 百分比，默认 `0` |
| 12 | `tempo` | 速度 | `!120` 或 `120` |
| 13 | `pitchBend` | 音高曲线 | Base64+RLE 编码，默认 `AA` |

> ⚠️ **第 7 个参数 `length` 的单位是毫秒，不是采样点。**
> 传 `44100` 会得到 44.1 秒的输出，而不是 1 秒。这是最容易踩的一个坑。

`cutoff` 为负数是正常的（表示右侧重叠区），程序允许负数参数。

## 支持的 flags

flags 形如 `g-3P60HG20`，会按长标记优先解析（`/` 分隔符会被忽略）。
**当前版本实际生效的只有下面这些**，其余标记会被解析但不影响输出：

| 标记 | 含义 | 取值 |
| --- | --- | --- |
| `g` | 性别/音色偏移 | `g-3` 表示 −3，单位约等于 1/100 半音，缺省用配置里的 `processing.gender` |
| `t` | 音高微调 | 整数，缺省 `0` |
| `A` | 按音高变化做振幅调制 | 整数，缺省 `0`（关闭） |
| `P` | 响度归一化强度 | `P60` = 60%，缺省 `100` |
| `He` | 强制启用循环拼接 | 开关型，出现即启用 |
| `HG` | growl（嘶吼） | `HG20` = 20% 强度 |

## 在 UTAU 中配置

1. 把 `resampler.exe` 放到一个固定目录（路径中**不要有空格和中文**，UTAU 的兼容性较差）
2. 打开 UTAU → `工具` → `选项` → `音源插件 / Resampler`
3. 选择「自定义」或直接在设置里填入 resampler 的完整路径
4. 确认后渲染一个音符试听

如果 UTAU 报「resampler 未响应」或输出为空，先用命令行手动跑一次同样的参数，
看程序自己的报错——绝大多数问题在命令行下都能一眼看出来。

## 日志与调试

UTAU 调用时看不到终端输出，可以把日志级别调高并重定向到文件：

```bash
resampler --log-level debug in.wav out.wav C4 100 "" 0 500 60 -50 100 0 !120 AA 2> debug.log
```

`--log-format json` 可以输出结构化日志，便于脚本分析。

## 性能提示

首次渲染某个样本时会做 Mel 分析和 F0 提取，结果会缓存为同目录下的 `.nrc` 文件
（zstd 压缩）。第二次渲染同一输入会明显更快。缓存键包含源文件大小、修改时间和配置指纹，
所以改了配置会自动失效重建——**不用手动删缓存**。
