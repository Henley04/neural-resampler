# アーキテクチャ

## データフロー

1 回のレンダリングの完全なパス（`src/core/pipeline.rs` に対応）：

```
UTAU 参数 / CLI 参数
        │
        ▼
  [1] 读取 WAV  ─────────────► AudioBuffer（单声道 f32）
        │
        ▼
  [2] 时间轴映射
        offset / consonant / cutoff / length
        → 源采样区间 [start, end)
        │
        ▼
  [3] 时序拉伸（rubato SincFixedIn 或线性插值）
        把源区间重采样到目标时长（BPM + 音符长度）
        │
        ▼
  [4] Mel 分析（origin_hop_size=128）
        → mel: [frames, 128]
        │
        ▼
  [5] 帧率转换 128 → 512（线性插值）
        │
        ▼
  [6] F0 生成
        FCPE(ONNX) / 内置 DSP / 纯乐谱
        + pitchBend + 性别偏移 + 颤音
        │
        ▼
  [7] 声码器推理（ort）
        (mel, f0) → waveform
        │
        ▼
  [8] 后处理（finalize 单一入口）：
        重采样 → 定长 → 响度归一化(P 插值) → 峰值限幅 → 音量(V) → 淡入淡出
        归一化/限幅/音量只发生一次，避免互相覆盖
        │
        ▼
  写出 WAV
```

## モジュールの責務

| モジュール | 責務 | 代替可能性 |
| --- | --- | --- |
| `adapters/utau.rs` | UTAU/OpenUtau 引数のアダプタ、バッチスケジューリング | 新しいエディタの追加は新しい adapter の実装のみで対応 |
| `core/protocol.rs` | 音名 ↔ MIDI ↔ Hz、フラグのパース、`pitchBend` のデコード | 純粋関数、ステートレス |
| `core/oto.rs` | `oto.ini` のパース（UTF-8 / Shift-JIS / GBK フォールバック） | 読み取り専用 |
| `core/audio.rs` | WAV の読み書き、Sinc リサンプリング、ゲイン、無音トリミング | hound に依存 |
| `core/feature.rs` | STFT、メルフィルタバンク、フレーム間補間 | 純 Rust + realfft |
| `core/f0/*` | `F0Extractor` trait の 3 実装 | `f0.backend` で切り替え |
| `core/pipeline.rs` | 上記ステップのオーケストレーション | 単一エントリポイント `render()` |
| `core/post_process.rs` | ラウドネス正規化、リミッター、フェードイン/アウト | 無効化可能 |
| `backend/*` | 推論バックエンド（ort / stub） | `vocoder.backend` で切り替え |
| `cache/f0_cache.rs` | Mel/F0 特徴量の zstd 永続化 | `cache.enabled` で無効化 |

## 主要な設計判断

### 1. 条件入力の変更によるピッチシフト

PC-NSF-HiFiGAN は F0 を明示的な条件として受け取るため、**F0 を変えるだけで正確に
ピッチをシフトできます**。従来のリサンプラーのようなリサンプリング＋ピッチシフト
（同時に長さも変わる）は不要です。長さ制御は Mel のタイムストレッチで独立に行われ、
両者は分離されています —— これが HiFiSampler の核心的なアイデアであり、本プロジェクトは
これを完全に保持しています。

### 2. 2 種類のフレームシフト（分析 128 / レンダリング 512）

分析段階では細かいフレームシフト 128 でタイムストレッチを行い、補間精度を高めます。
ボコーダはフレームシフト 512 の Mel しか受け付けないため、ボコーダに渡す前に
線形補間でフレームレートを落とします（`origin_hop_size → hop_size`）。

### 3. F0 の 3 段フォールバック

```
FCPE ONNX  ──失败──►  内置 DSP（DIO 风格谐波打分）  ──失败──►  纯乐谱 F0
```

いずれかの段階で失敗しても、レンダリングは中断されずフォールバックするだけです。
そのため、モデルがない・壊れているマシンでも（音質は低下しますが）音を出せます。

### 4. キャッシュキー

キャッシュキーには次を含みます：ソースファイルのパス、ファイルサイズ、mtime
（秒＋ナノ秒）、Mel パラメータのハッシュ、F0 パラメータのハッシュ、サンプリング
レート。いずれかが変わると無効化して再構築するため、サンプル差し替え後に古い
特徴量を読むことはありません。

### 5. スレッドモデル

`Session` は `Sync` ではないため、バッチレンダリングでは各 worker スレッドが
それぞれバックエンドインスタンスを 1 つ保持します（`--jobs N`）。シングルスレッドの
レンダリングでは同じインスタンスを再利用し、モデルの再読み込みを避けます。

## 拡張ポイント

* **新しいエディタ**：`src/adapters/` の下に新しいモジュールを追加し、`RenderRequest` を生成するだけです。
* **新しい F0 バックエンド**：`F0Extractor` trait を実装し、`core/f0/mod.rs` のファクトリ関数に文字列キーを登録します。
* **新しいボコーダ**：`backend::Vocoder` trait を実装します。ONNX のままであれば、設定の入出力ノード名を変えるだけで済みます。
* **新しい実行プロバイダ**：`backend/ort_backend.rs` の `build_providers()` に分岐を追加し、cargo feature でコンパイルを制御します。
